# Personal Contribution
**What did you personally contribute to the project? Describe specific tasks, ideas, design**
**decisions, or work that you completed?**
- Planning wise, I am responsible for the game's buff (positive effect), debuff (negative effect), duel, shop and path branching mechanics.
- Design wise, I drafted and printed the entire game board in Figma.
- I contributed partially to the money system and some small rule revisions.

# Collaboration:
**How did your group work together?**
- We worked in a very disorganized way. It was impressive that we all managed to establish contact within like six minutes of the project's announcement, but that was about as organized as we got. We knew what things needed to be done, we would talk about it in a shared chat and then someone would step up to claim the job and do it. Or sometimes someone would do some work and then ask the group to take a look and suggest changes. A fun and loose development strategy if anything. We didn't have much disagreement beyond simply discouraging features that were too complicated for the intended scale of the project, however some did make it to the playtest, at which they ended up getting cut from the final submission.

# Game Design Reflection:
-  **What worked well in your game?**
	- The game board ✌️. It was appropriately scaled and the branching system worked in an unexpected way that reduced player duels.
	- Buff, debuff, duel systems. They had good presence and value in the playtest.
-  **What did not work as well as you hoped?**
	- The health system, unified shop system, and car upgrade mechanics, these were almost entirely absent from the playtest.
-  **What did you learn about your game's rules?**
	- There were too many of them. We need to reduce the complexity of the game as some mechanics never naturally propagated during the playtest as a result of overcomplicated rules.
-  **Did playtesting reveal anything unexpected?**
	- Yes, the game has too many mechanics that weren't properly fleshed out, which ended up making features feel shallow.
-  **If you continued developing the game, what would you change?**
	- Add more buffs and debuffs so that there's six of each. This way they map properly with the six faces of a standard die. 
	- Combine the money and health systems. Money was already the points system in the game.

# Theory Reflection
- **Which Types of Fun did you personally experience while playing the game?**
	- Fellowship/People, Submission, 
- **Which Bartle Player Type do you think best matches the game?**
	- Socializers.
- **Why?**
	- I think that the game is ultimately fun because of the other players involved in the game--seeing their experience of it and the way that they can interact via the dueling system and how a single player can effect every other player via a global effect system. 
	  
	  The nature of the game doesn't have much re-playable mystery to suggest Explorer-type players. Randomness of events and rolls doesn't suggests competition or Killer-type players, nor does it suggest much achievement to be had, disqualifying the suggestion of Achiever-type players.

# Learning Reflection:
**What did you learn about:**
- **Game design**
	- Determine project scale before planning features.
- **Designing rules**
	- Make rules iteratively per feature, so that we don't have to simultaneously figure out the rules for all features at the same time.
	- Write rules in a way they only need to be read when they're needed.
- **Playtesting and iteration**
	- It's hard to remember a large set of rules in one read. This makes playtesting a slog as I have to constantly reference rules again and again as I play. Perhaps this is just a me issue with a cooked attention span.
- **Working as a member of a design team**
	- Pay close attention to other members' suggestions as they could inspire you.
