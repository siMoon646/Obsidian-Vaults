# Chapter 1:
### Binding Times 
1) Language Definition Time Binding:
	- Arbitrarily decided at language design.
	- Decides meaning (semantics)
2) Language Implementation Time:
	- Decides mechanism -- how to implement meaning in hardware.
	- Deferred sometimes, as platforms vary.
	- Some languages will make guarantees to avoid ambiguity -> sometimes a part of the language definition time binding.
3) Compile Time Binding:
	- Compiler binds an variable to its relevant type/data structure.
	- Checks to see if use of variable is valid, given type/data structure.
4) Link Time:
	- An identifier gets bound to implementation code (think writing header
	files in C++ and then implementation file.
5) Load Time: 
	- Loading the contents of the program into memory.
6) Run Time:
	- Identifiers are bound to specific values.
	- Most flexible binding--things decided when the program runs.

### Programming Paradigms/Styles:
1) Imperative:
	- von Neumann architecture:  
		- uniform representation of instructions and data in main memory.
	- Fetch-Decode-Execute cycle:
		1) Fetch: CPU retrieves the next instruction from memory (using program counter).
		2) Decode: instructions are interpreted (or compiled then interpreted).
		3) Execute: performs instructions from decoding step.
		4) go back to step 1
	- Use of assignment to modify the values of variables (abstractions of memory cells).
2) Functional :
	- Function-based programming.
	- Functions are first-class entities.
	- Programmer describes computation by calling series of function that cascade set of return values to each other.
	- Typically doesn't involve variables and assignment.
	- Side effects are usually absent from functional programming.
	- Recursion is a primary means of repetition.
	- Goal:
		- To bring programming closer to mathematics.
3) Object-Oriented :
	- Develops a solution to a problem as a collection of objects communicating by passing messages to each other.
	- Unifies concepts of data + procedural abstraction through the constructs of classes and objects.
	- Functional Programming's "closures" is a precursor to OOP
4) Logic/Declarative :
	- Programming that describes *what* is to be computed not *how*
	- Referred to as rule-based
	- Usually becomes less efficient as layers of abstraction takes away the ability to fine-tune program's finer details.
5) Bottom-up :
	- Solving a family of problems, by building a language around that family of problems
6) Synthesis :
	- Describes the combination of programming language paradigms/styles. (styles like functional working well with bottom-up)

# Chapter 2: Formal Languages & Grammars:
## Formal Languages:
### Kleene Closure
- Represents the set of all possible strings formed via zero or more concatenations of the same set of characters.
- Ex:$$(meat)^* \supset meatmeatmeat\text{, 
  "meatmeatmeat" is one of the elements in (meat)$^*$}$$
### What Is A Formal Language?
- A set of strings
- $\text{Formal language }L \subset \Sigma^* \text{, where each string from } \Sigma^* \text{ in } L \text{ is called a sentence}$
### Finite Language
- Formal language with finite number of sentences.

## Regular Expressions & Regular Languages:
- Regular expressions have their own alphabet + syntax, not to be confused with the alphabet and syntax of a regular language.
- A formal language.
### Operators Of Regex:
- \* : Kleene closure operator; for regex $r$, $r^*$ is zero or more concatenations of r to itself.
- $\emptyset$ : the empty set
- +: Concatenation operator.
- ( : delimiter for indicating opening of an expression
- ) : delimiter for indicating closing of an expression.

### Finite-State Automata: 
- A mechanism that can determine
- if a string is a sentence in a target language.
## Grammars & Backus-Naur Form:
### Formal Definition Of A Grammar:
- $G = ({V,\Sigma,P,S})$, where:
1) $V$ - non-terminal alphabet
2) $\Sigma$ - terminal alphabet
3) $P$ - finite set of production rules, each in the form of $X -> y$, where $x \text{ and } y$ are strings over $\Sigma \cup V$ and $x \cancel{=} y$
4) $S$ - the start symbol, $S \epsilon V$ 

- Productions are impossible without non-terminal alphabet symbols.
#### Example:
$$\begin{align}S \rightarrow bT \\ T \rightarrow acT \\ T \rightarrow \epsilon \end{align}$$, where:
$V = \{S,T\}$
$\Sigma = \{ a, b, c\}$
$P = \text{the diagram above}$
$S = S$
#### Regular Grammar By Chomsky Hierarchy:
-  Defines regular grammar:
	- Is a right-linear grammar: $$\begin{align} X \rightarrow zY \\ X \rightarrow z \end{align}$$
	- is a left-linear grammar:$$\begin{align} X \rightarrow Yz \\ X \rightarrow z \end{align}$$
- linear grammar $\leftrightarrow$ regular grammar
- Define a class of languages known as regular languages.

##### Properties Defining Regular Languages:
1) Denoted by regular expressions
2) Generated by regular grammars
3) Recognized by finite state automata

# Chapter 5: Scheme
## Overview
- Functional, dynamically typed dialect of Lisp.
- Fully parenthesized **prefix** notation (S-expressions); code and data are both lists.
- Run in a **REPL** (Read → Eval → Print → Loop). File extension: `.scm`

## Hello World
```scheme
(display "Hello, World!")
(newline)
```

## Basics
- Comments: `;` (to end of line)
- Literals evaluate to themselves: `42 ; 42`, `"hi" ; "hi"`
- Types: numbers (`42`, `3.14`, `1/3`), booleans (`#t`, `#f`), strings, symbols (`'a`), empty list (`'()`)
- **Only `#f` is false**; `0` and `'()` are true.

## Procedures
- Procedures = Java's functions. Call: `(<procedure-name> <args...>)`
- **Evaluation rule:** evaluate the operator and all arguments, then apply.
- Operators are procedures with values: `+ ; #<procedure:+>`
- Not necessarily binary: `(+ 1 2 3) ; 6`
- Infix → prefix: `(1 + 2 + 3) * (4 - 5) + 6` → `(+ (* (+ 1 2 3) (- 4 5)) 6) ; 0`
- Every `(` is a call: `((+ 1 2))` is an error (3 is not a procedure).

## `define` & Identifiers
```scheme
(define pi 3.1415)
pi   ; 3.1415
```
- Identifiers may contain `- ? ! * < > =` etc.
- **Forbidden** in identifiers: whitespace, `( ) [ ] { }`, `" , ' ` ;` `|` `\`, and a leading `#`
	- Can't look like a number: `123`, `+5`, `-2.5` are numbers, not names (but `+`, `-`, `...`, `1+` are valid names)
	- A lone `.` is reserved (used in dotted pairs)
- Conventions: `?` = predicate (`null?`), `!` = mutation (`set!`), `->` = conversion (`string->number`)

## `lambda`
- `(lambda (<params>) <body>)` creates an anonymous procedure.
```scheme
((lambda (x) (+ x 1)) 5)                ; 6
(define successor (lambda (x) (+ x 1))) ; give it a name
(define (successor x) (+ x 1))          ; shorthand, same thing
(successor 5)                           ; 6
```
- Procedures are **first-class**: they can be stored, passed and returned.
- Local variables: `(let ((x 2) (y 3)) (* x y)) ; 6`

## Special Forms
- `define`, `lambda`, `if`, `cond`, `quote`, `let`, `and`, `or`
- **Rule:** their arguments are **not** all evaluated before running. Each form decides what to evaluate.
	- `define` doesn't evaluate the name; `lambda` doesn't evaluate the body until called; `quote` never evaluates.
	- `(if #t 1 (/ 1 0)) ; 1`, since the else branch is never evaluated.

## Conditionals
```scheme
(if <test> <then> <else>)
(if (> 3 2) 'yes 'no)   ; yes

(cond (<test1> <expr1>)
      (<test2> <expr2>)
      (else <default>))
```
- `cond` checks tests top to bottom and returns the first match.
- Don't wrap a non-call test in parentheses: `(if (x) ...)` calls `x`.
- Common tests: `= < >`, `null?`, `pair?`, `zero?`, `even?`, `equal?`, `and`, `or`, `not`

## Quote & Symbols
- `(quote a) ; a` returns the **symbol** `a`, unevaluated. Sugar: `'a`
- `(+ 1 'a)` is an error.
- `'(1 2 3)` is list data; `(1 2 3)` is an error (1 is not a procedure).

## Pairs
| Operation   | Procedure    | Meaning                                       |
| ----------- | ------------ | --------------------------------------------- |
| Create Pair | `(cons x y)` | constructs a pair of `x` and `y`              |
| Get First   | `(car p)`    | Contents of Address Register: left value     |
| Get Second  | `(cdr p)`    | Contents of Decrement Register: right value  |

```scheme
(define p (cons 10 20))   ; same as '(10 . 20)
p         ; (10 . 20)
(car p)   ; 10
(cdr p)   ; 20
```

## Lists
- A list is `'()` or a pair whose `cdr` is a list.
```scheme
(cons 1 2)              ; (1 . 2), a pair (not a proper list)
(cons 1 (cons 2 '()))   ; (1 2), a proper list
```
- On a list, `car` = first element, `cdr` = rest. `(cadr L)` = `(car (cdr L))`

| Procedure            | Example                                      |
| -------------------- | -------------------------------------------- |
| `(list a b ...)`     | `(list '(1 3) '(2) '()) ; ((1 3) (2) ())`    |
| `(length L)`         | `(length '(1 (2 3) 4)) ; 3`                  |
| `(append L1 L2 ...)` | `(append '(1 2) '(3)) ; (1 2 3)`             |
| `(reverse L)`        | `(reverse '(1 2 3)) ; (3 2 1)`               |
| `(null? L)`          | `(null? '()) ; #t`                           |

> [!tip] `cons` vs `list` vs `append`
> ```scheme
> (cons   '(1 2) '(3 4))   ; ((1 2) 3 4)
> (list   '(1 2) '(3 4))   ; ((1 2) (3 4))
> (append '(1 2) '(3 4))   ; (1 2 3 4)
> ```

## Recursion on Lists
- Pattern: **base case** `(null? L)`, then **recursive case**: use `(car L)`, recurse on `(cdr L)`.
```scheme
(define (sum L)
  (if (null? L)
      0
      (+ (car L) (sum (cdr L)))))
(sum '(1 2 3))   ; (+ 1 (+ 2 (+ 3 0))) = 6
```

## Higher-Order Procedures
- Take a procedure as input and/or return one.
- `(map <procedure> L)` applies the procedure to each element: `(map successor '(1 2 3)) ; (2 3 4)`
- `(apply + '(1 2 3)) ; 6`
- `(filter even? '(1 2 3 4)) ; (2 4)` (Racket / SRFI-1)
```scheme
(define (my-map f L)
  (if (null? L)
      '()
      (cons (f (car L)) (my-map f (cdr L)))))

(define (make-adder n)       ; returns a procedure (a closure)
  (lambda (x) (+ x n)))
((make-adder 5) 10)          ; 15
```
